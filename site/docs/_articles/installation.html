Installation

L'onglet Installation (groupe « Installation du drone ») montre en direct l'attitude du drone sur un modèle 3D, l'état de la carte (ce qui empêche l'armement, batterie, charge du processeur), le GPS et les informations du firmware. C'est la première étape de la mise en route : on vérifie que le drone virtuel bouge comme le vrai.

Le modèle 3D

Le grand cadre du haut affiche un modèle 3D du drone. Il suit l'attitude envoyée par la carte, environ 30 fois par seconde. Le modèle dépend du type de mixeur réglé dans la carte (quad, hexa, tricoptère, avion…).

  • Lacet (Yaw) :, Pitch:, Roll: : angles du drone, en degrés (« deg »), affichés en haut à gauche du cadre.
  • Réinitialiser l'axe Z, écart: … deg : bouton en haut à droite. Il remet le lacet du modèle 3D à 0 dans l'affichage, pour que le modèle regarde droit devant. Le nombre affiché est la correction appliquée. Rien n'est envoyé à la carte : c'est seulement l'affichage.
  • Deux cadrans (horizon artificiel et cap) s'affichent en bas à droite seulement avec les firmwares de navigation (TRUENAV, TRUENAV_LIGHT) et le simulateur. Ils montrent les mêmes valeurs que le modèle.

Vues « Profil » et « Dessus »

Deux boutons en bas à gauche du cadre choisissent la vue. Le choix est gardé d'une session à l'autre.

  • Profil : la vue habituelle, le drone vu de côté.
  • Dessus : le modèle est incliné pour être vu par-dessus. Des repères s'ajoutent et suivent le modèle quand il bouge :
    • le mot AVANT avec une flèche ▲, juste devant le nez du drone ;
    • le numéro de chaque moteur, dans un rond, au-dessus de chaque moteur.

Les numéros de moteurs suivent la numérotation du mixeur Quad X standard :

MoteurPosition (drone vu de dessus, nez vers l'avant)
1arrière droit
2avant droit
3arrière gauche
4avant gauche
Les numéros ne sont dessinés que sur le modèle du quad X. Ce même modèle sert aussi aux mixeurs Quad +, Quad X 1234 et X8 coaxial : avec ces mixeurs, les numéros affichés ne correspondent pas forcément à vos moteurs. Pour les autres modèles (hexa, tricoptère, avion…), seul le repère AVANT s'affiche. Dans tous les cas, l'ordre réel des moteurs se vérifie dans l'onglet Moteurs, hélices retirées.

Vérifier que le modèle suit le drone

  1. Posez le drone à plat. Le modèle doit être à plat lui aussi.
  2. Levez le nez du drone : le nez du modèle doit monter.
  3. Penchez le drone vers la droite : le modèle doit pencher vers la droite.
  4. Tournez le drone sur lui-même : le modèle doit tourner dans le même sens.
  5. Si un mouvement est inversé ou décalé, corrigez l'Alignement de la carte dans l'onglet Capteurs.

Le calibrage de l'accéléromètre (drone posé à plat) se fait aussi dans l'onglet Capteurs, cadre Accéléromètre, bouton Calibrer. Il n'y a pas de bouton de calibrage dans l'onglet Installation.

Cadre « Info Système »

Valeurs relues environ 4 fois par seconde.

  • Paramètres empêchant l'armement: : la liste des raisons pour lesquelles la carte refuse d'armer (par exemple RXLOSS : aucun signal du récepteur ; ANGLE : drone pas assez à plat ; MSP : connexion au logiciel active). Passez la souris sur un mot pour lire son explication. Quand plus rien ne bloque, le texte Armement autorisé s'affiche.
  • Tension de la batterie: : tension mesurée, en V.
  • Mah consommés: : capacité consommée depuis la mise sous tension, en mAh.
  • Courant consommé: : courant instantané, en A.
  • RSSI: : force du signal radio. Le logiciel calcule un pourcentage (0 à 100) mais l'affiche suivi de « dBm » : lisez cette valeur comme un pourcentage.
  • MCU: : modèle du processeur de la carte.
  • Charge CPU : : charge du processeur, en %.
  • Vitesse de boucle : : fréquence du gyro, puis fréquence de la boucle PID, en Hz (« k » = kHz). Exemple : 8.0k / 4.0k. Vide si la carte ne donne pas la durée de boucle.
  • Température du CPU: : température du processeur, en °C. Quand la carte ne donne pas de température, le texte « Aucune prise en charge de l'API MSP avant 1.46 » s'affiche, même avec un firmware récent (c'est le cas du simulateur).

Cadre « GPS »

  • Accroche: : Vrai (vert) quand le GPS a une position, Faux (rouge) sinon.
  • Nombre de satellites : : nombre de satellites utilisés.
  • Latitude: et Longitude: : position en degrés. Un clic ouvre la position dans Google Maps (navigateur).

Le GPS doit être déclaré dans l'onglet Ports et réglé dans l'onglet GPS.

Cadre « Info Firmware »

  • Carte : : nom de la carte (cible du firmware).
  • Firmware : : identifiant et version. Le firmware TRUEGLIDE s'annonce volontairement « BTFL » suivi de la version, car il garde la base Betaflight 2026.6.2.
  • API MSP : : version du protocole de dialogue entre la carte et le logiciel.
  • Date de compilation : : date à laquelle le firmware a été compilé.
  • Type de construction : : Compilation locale ou Construction Cloud (firmware construit par le serveur de Betaflight).
  • Info de compilation : : liens Log et Configuration vers le serveur de construction, seulement pour une construction Cloud. Sinon : « Aucune information de construction disponible » ou « Serveur indisponible ».
  • Micrologiciel: : le lien Options ouvre la liste des options compilées dans le firmware (par exemple USE_GPS). Le lien Télécharger n'apparaît que pour une construction Cloud.

Boutons du mode Expert

Ces deux boutons n'apparaissent que si le mode Expert est actif (icône de clé dans la barre du haut, « Activer/désactiver le mode expert »).

  • Réinitialiser les paramètres : remet tous les réglages de la carte à l'état non configuré. Une fenêtre Confirmer demande de choisir Annuler ou Réinitialiser.
  • Activer le Boot Loader / DFU : redémarre la carte en mode de chargement de firmware, pour la flasher (voir Flasher le Firmware).
Avant Réinitialiser les paramètres, faites une sauvegarde : onglet Ligne de commande (CLI), commande diff all, et gardez le texte. Ce n'est pas une « remise d'usine » : selon le logiciel lui-même, il peut être nécessaire de reflasher le firmware pour se reconnecter.

Cadre « Sonar »

Affiché seulement si la carte a un sonar actif. Altitude : distance mesurée, en cm.
